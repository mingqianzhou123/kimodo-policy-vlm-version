# Kimodo 稀疏约束与关节转换诊断 — 2026-11-17

## 结论

稀疏约束没有丢失：目标构造、坐标、归一化、mask、未来帧索引和实际网络输入均通过检查；改变目标会使输出朝相应方向变化。但它是学习到的条件响应，不是硬约束求解。当前无文本、密集实测历史、滚动重规划的用法下，原始模型输出仍有厘米到十几厘米误差。历史条件组织对结果有明显影响；增加采样步数或简单提高 CFG 不能解决。

关节问题需要拆开处理：

- **超限主要已存在于生成旋转中**：换成最近单轴投影仍有相同量级的超限，不能归因于关节顺序或矩阵日志实现错误。现有转换没有限位保护。
- **跨重规划跳变在转换前已存在**：相邻窗口的旋转矩阵已经相差 40–144°；这属于生成与窗口交接问题，还叠加了实测历史与旧参考不一致。
- **±π 分支又放大了部分标量跳变**：一个 20.48° 的矩阵变化被转换成 338.66° 的关节标量变化。这个放大部分属于转换与连续性处理问题。

本轮只做诊断和离线对照，没有改变默认采样、关节转换或 Arena 执行行为，也没有把修正过的轨迹送入仿真。尚未证明已经解决精度问题。

## 实验范围和可复现性

在开发机 `humanoidVLA/vlm version` 使用同一 Kimodo-G1-RP-v1 真权重，在 GPU 2 完成 **56 次推理**：

- `runs/constraint-diagnosis-20261117-r2`：32 次，保持/伸手 × plan 0/3 × 8 种条件。
- `runs/constraint-diagnosis-20261117-r3`：24 次，相同输入窗口 × 6 种历史条件。
- plan 0 是启动后 0.1 秒的首次生成，3 帧实测历史、未来关键帧 33；plan 3 在 1.6 秒，48 帧实测历史、未来关键帧 0/15/30/49。
- 未来关键帧误差表只统计正索引（排除已经到期的 frame 0），全部是未执行动作的旋转 FK 腕误差，不是 SONIC 跟踪误差。
- 除明确改变的变量外，每对实验使用相同权重、输入历史、目标和噪声。缩短左侧 padding 的对照也保留了对应有效 token 的原始噪声。
- 8 个 checkpoint/config/stats 文件哈希与旧运行完全一致；8 个 baseline 重放的 50×417 输出与旧保存结果最大绝对差均为 **0**。
- 第一轮 r1 在读取旧 hold 记录缺少的 `witness_joint_pos` 字段时停止，没有产出推理结果；已改为兼容可选字段，保留记录，不计入 56 次。

## 稀疏约束是否正确生效

### 输入链检查

每个双手关键帧有 26 个已知特征：smooth root XZ 两个、双腕与虚拟手端位置 12 个、双腕全局旋转 6D 共 12 个。维度/关节名与 G1Skeleton34 一致。

1. 用独立合法关节姿态生成完整特征，再构造稀疏条件，26 个值逐项相等，容差 1e-6。这覆盖位置的 root 平移、Y-up 高度、全局旋转约定与左右手索引。
2. 运行中检查归一化后的值、mask、未来有效帧，以及真正进入 root Transformer 的拼接输入；共通过 **3,400 次 guidance 调用、6,600 次 root Transformer 输入检查**。
3. 本地实现与官方 [条件构造源码](https://research.nvidia.com/labs/sil/projects/kimodo/docs/_modules/kimodo/motion_rep/reps/kimodo_motionrep.html) 的 root XZ、相对位置和全局旋转约定一致；CFG 使用无文本约束分支，与官方 [CFG 定义](https://research.nvidia.com/labs/sil/projects/kimodo/docs/_modules/kimodo/model/cfg.html) 对应。

### 同一噪声下改变目标

只把双手位置目标沿模型坐标 X 平移 5 cm，root 与旋转条件不变：

| 窗口 | 左/右腕位置字段沿 X 的响应，cm |
|---|---:|
| 保持 plan 0 | 4.11 / 5.45 |
| 伸手 plan 0 | 3.95 / 5.37 |
| 保持 plan 3 | 2.57 / 2.80 |
| 伸手 plan 3 | 2.60 / 2.66 |

说明网络读到了目标，且早期响应方向和幅度合理；后期的响应被削弱。它不等于绝对位置准确：输出可以沿目标方向移动，同时保持原有偏差。

### 哪些设置影响精度

以下均为未来正索引关键帧旋转 FK 平均误差，左/右腕，cm；每格是一种固定输入和噪声的诊断，不是多种子总体性能。

| 对照 | 保持 p0 | 保持 p3 | 伸手 p0 | 伸手 p3 |
|---|---:|---:|---:|---:|
| 原设置：CFG 2，50 步，全部历史 | 9.05 / 6.07 | 10.20 / 16.83 | 9.84 / 5.72 | 10.13 / 16.36 |
| 关闭未来稀疏条件 | 10.53 / 14.18 | 11.16 / 43.66 | 13.13 / 14.61 | 13.57 / 43.51 |
| CFG 1 | 9.98 / 2.65 | 6.98 / 15.07 | 11.46 / 2.61 | 6.49 / 15.01 |
| CFG 4 | 10.21 / 10.16 | 35.23 / 34.87 | 11.81 / 9.94 | 26.70 / 29.65 |
| 200 步 | 9.14 / 6.87 | 10.53 / 17.05 | 9.92 / 6.53 | 10.11 / 16.40 |
| 只保留最近 1 帧历史条件 | 5.10 / 7.10 | **6.26 / 3.80** | 6.22 / 6.14 | **6.23 / 5.07** |
| 未来改为完整目标姿态条件 | 3.99 / 3.92 | 3.92 / 7.66 | 4.73 / 4.66 | 4.41 / 8.61 |

“最近 1 帧”只改变历史 feature mask，没有改变时间轴、有效 token 或噪声。后期改善明显，说明当前历史条件组织确实是影响因素；但它同时移除了旧姿态和速度等信息，不能把全部改善都解释为“帧数太多”。替换成静止初始历史后，plan 3 仍约 7–12 cm，历史漂移也不是唯一原因。

去掉到期后的 future frame 0 目标几乎无改善；缩短左侧 padding 没有一致改善；去掉历史速度/接触字段也没有稳定解决问题。提高 CFG 会同时强化全部历史与未来条件，并非只提高未来手部目标权重。

官方说明模型输出不保证精确命中约束，通常需要后处理，并明确指出 G1 后处理仍存在局限；同时建议控制非 root 约束的关键帧数量。这支持检查历史组织方式，但不能替代本次实测。[官方局限说明](https://research.nvidia.com/labs/sil/projects/kimodo/docs/key_concepts/limitations.html)

### 为什么不能直接覆盖输出位置字段

仅在离线诊断中，把输出的 mask 位置强制覆盖成目标后，位置字段误差成为零，但旋转 FK 腕误差仍为 **6.38–11.73 cm**。原因是 Kimodo 分别输出位置特征和旋转特征，写对腕位置字段不会自动求解肩、肘的旋转。该反事实结果保存于 `diagnosis-summary.json`，没有执行或冒充模型精度。

## 超限、跳变分别来自哪里

`scripts/diagnose_joint_conversion.py` 从保存的 417 维输出重建 30 Hz 旋转，再复现 50 Hz 插值与发送关节。独立 SciPy 矩阵日志计算与当前转换结果最大差 <5e-7 rad；66 个合法姿态（含限位端点）往返检查通过，未发现关节顺序或静态坐标偏置错误。

| 审计 | 保持 | 伸手 |
|---|---:|---:|
| 原始 30 Hz 预测中转换后超限帧 | 173/400 | 168/400 |
| 原始旋转改用最近单轴投影后超限帧 | 174/400 | 169/400 |
| 50 Hz 发送参考超限帧 | 108/200 | 104/200 |
| 50 Hz 最近单轴投影后超限帧 | 109/200 | 104/200 |
| 已超限关节的超限幅度中位数 / p95 / 最大值，度 | 1.91 / 14.43 / 55.45 | 1.86 / 13.22 / 40.85 |

400 帧指 8 个完整预测窗口，各 50 帧，有时间重叠；200 帧指 8 个已发送 chunk，各 25 帧，不含最初 5 步 warmup，最后 5 个参考晚于旧仿真的结束时间。因此它们是参考数据计数，不是 400/200 个独立执行样本。大量小幅踝超限与少量严重超限并存。

单轴偏离在 50 Hz 参考中平均约 1.5–1.6°，p95 约 5.3–6.7°，最大约 44°。模型的自由旋转确实不总符合 G1 单轴关节结构；不过把旧投影换成最近单轴投影后，关节角平均仅变化约 0.01°，不能指望仅换投影公式解决大部分问题。

**角度分支的具体例子：**伸手参考第 138→139 帧，右髋 yaw 的原始局部矩阵只变化 20.48°，但关节标量从 -2.832 到 3.078 rad，差 338.66°。保持参考右腕 roll 的最大标量差为 254.49°，对应矩阵差仍有 98.45°：这里既有原始运动不连续，又有分支放大。不能把所有数百度跳变都称为模型真的转了数百度。G1 是有限转角关节，简单 unwrap 也可能违反限位，连续性和限位必须一起处理。

**跨窗口的具体例子：**保持的交接矩阵最大差范围为 40.46–115.80°，伸手为 42.64–144.12°，与标量交接差接近。它们在矩阵转换前已经存在。部分交接是新参考向实测姿态回落，部分新参考本身也离实测姿态很远：伸手 plan 4 的最大跳变关节是左髋 yaw，新参考距当时实测约 -87.06°，旧参考距实测约 +20.04°，形成约 -107.10° 的交接。当前流程没有已执行边界的硬保持或重叠连续性约束。

## 后续优先级

1. 保留原设置为诊断基准，先验证较短/稀疏历史和显式连续边界的 A 变体。最近 1 帧的离线结果有改善，但还不能直接改成正式默认值。
2. 在生成后增加关节域的合法性与连续性处理，同时重新测量腕目标误差；不能只夹限，再把偏离目标的轨迹说成已修好。
3. 若要求厘米级精确到位，需要可验证的 G1 约束求解/优化或适配训练，而不是继续假设原生稀疏条件等于精确 IK。当前证据不足以证明某一具体求解器或训练方案已经有效。

VLM、视觉注入和夹爪仍后置。此次诊断识别了条件响应不足、历史组织影响、原始轨迹缺陷及转换分支放大，但尚未量化它们对最终执行误差各占多少。
