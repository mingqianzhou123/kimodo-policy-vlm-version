# IK 保持阶段冗余关节稳定（2026-11-17）

## 要回答的问题

上一轮 IK 已将参考双腕精确投到目标上，但保持期仍追随 Kimodo 不断变化的姿态先验，导致肩、肘、腕冗余关节持续运动。本轮只改变 IK 的保持逻辑，检验去除这些运动能否让实际双腕稳定进入 3 cm。不接 VLM，不改变 Kimodo 权重/条件、SONIC、根部目标、到达期限或关节速度上限，也不进行速度优化。

验收沿用上一轮：到达期限 1.2 s 后，每一个 50 Hz 实际执行帧，两只腕的世界位置误差同时 ≤3 cm。分别报告 1.2–4 s、1.2–8 s 和 4–8 s；不能用后半段通过替代全程通过。

## 最终结果

修正版 r2 的保持与伸手都通过了本轮的严格验收：到达期限后 1.2–8 s 各 340 帧，实际双腕每帧同时 ≤3 cm，且参考关节在整个保持区间（含重规划交接）完全不变。

| 任务 / 版本 | 实际平均误差，左 / 右（cm） | 实际最大误差，左 / 右（cm） | 双腕同时 ≤3 cm 帧占比 | 保持区间最大单关节参考变化范围 |
|---|---:|---:|---:|---:|
| 保持 / 原 IK | 2.74 / 1.70 | 3.42 / 2.57 | 62.35% | 31.28° |
| 保持 / ik-hold r2 | 2.38 / 2.06 | 2.89 / 2.15 | **100%** | **0°** |
| 伸手 / 原 IK | 2.35 / 2.17 | 3.14 / 3.05 | 97.06% | 33.43° |
| 伸手 / ik-hold r2 | 2.18 / 2.40 | 2.38 / 2.50 | **100%** | **0°** |

表中均统计 1.2–8 s。1.2–4 s 和 4–8 s 两个分段也分别全部通过。实际误差来自 Arena 实测腕部世界坐标对合法 oracle 腕目标的距离；不是 IK 的参考 FK 残差。参考关节变化为零不表示实际机器人关节完全静止，SONIC 仍在物理环境中跟踪固定参考。

参考 FK 的全程最大双腕位置误差：保持左/右 4.32e-7 / 4.44e-7 m，伸手 1.98e-6 / 1.83e-6 m。两项均无参考关节越限。伸手全程最大相邻参考关节步长 3.36°，低于 4 rad/s 对应的 50 Hz 上限 4.58°；保持参考步长为零。根部跟踪在 1.2–4 s 的平均位置误差仍约 2.14 / 2.20 cm（保持 / 伸手），因此本轮没有消除物理跟踪偏差，只是消除了会继续扰动跟踪的冗余参考运动。

原 IK 数据沿用上一轮已保存的 8 秒基线；本轮新跑 r1、r2 各两项，共四次真实 Arena 执行。固定 seed 1000、相同初始状态、模型权重、tracker 和 Arena 文件指纹已核验，首个原生 Kimodo 预测逐值一致。结论限于这一个站姿初始化、合法约 5.64 cm 伸手目标和 8 秒时长；尚未验证多初态、多目标、扰动、接触或抓取。保持左腕最大 2.89 cm 距阈值仍较近，不能由一次通过推断所有场景稳定。没有接入 VLM，也没有优化速度。

## 保留与改动

- 原 IK 完整保存到 `snapshots/ik-before-hold-stability-20261117/`，115 个文件逐一对照 `continuous-ik-manifest.json` 校验。本地与开发机均保存。
- 原 `--trajectory-projection ik` 路径保留，默认选项不变。新增 `--trajectory-projection ik-hold`。
- 仅当相邻控制时刻的手部**目标位置及姿态都不变**时（按位置 1e-6 m、旋转 1e-6 rad 容差识别），停止使用新 Kimodo 姿态先验，改为保持上一参考姿态。
- 若上一参考 FK 已满足双腕、双脚位置误差 ≤1e-5 m、姿态误差 ≤1e-4 rad，且关节在限位内，直接保持其关节值。阈值用于识别数值上已到位的参考，不是实际机器人到位判定。
- 若目标未变但参考未到位，继续有速度/限位约束的 IK，并以旧参考作为姿态先验；若目标改变，恢复原 IK 的移动目标求解。
- 每个新规划包从执行端最后**实际消费的参考关节**开始。没有跨窗口拿尚未执行的预测末帧作保持姿态，也不把实测漂移当作新参考。
- 根部参考与双脚目标继续固定于初始站姿；腕轨迹仍按原 1.2 s 合法 oracle 路径给出。没有把目标 witness 关节作为输出动作。

保持任务的初始参考本来已满足手脚目标，因此该诊断中保持输出会退化为初始合法固定参考，这是预期对照，不是声称 Kimodo 学会了保持。伸手仍先按原 IK 到达，再停止冗余姿态变化。

## 可复现命令

在开发机 `/root/workspace/humanoidVLA/vlm version` 内，选空闲且不同的两张 GPU：

```bash
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python scripts/run_oracle.py \
  --run-id ikhold-new-hold --mode hold --steps 400 \
  --variant bounded --joint-speed 4 --support-constraints root \
  --hand-constraints continuous --trajectory-projection ik-hold \
  --policy-gpu 5 --sim-gpu 6
```

伸手改 `--mode reach`；原 IK 对照改 `--trajectory-projection ik`。run-id 必须新建。

```bash
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python scripts/review_ik_hold.py \
  runs/continuous-ik-hold-20261117-r1 runs/continuous-ik-reach-20261117-r1 \
  runs/ikhold-stable-hold-20261117-r2 runs/ikhold-stable-reach-20261117-r2
```

`scripts/audit_ik_hold_replay.py` 对原 IK 与保存快照进行相同输入重放；保持、伸手各取窗口 0、3、15，六组关节输出逐值一致，最大差 0。

## 边界数值修正

首版 r1 用 1e-9 判定目标相同，忽略了单帧/批量 float32 FK 的约 1e-7 数值差异。每个规划包第一帧因此错误恢复了模型姿态先验，其余帧能正常保持。保持任务虽已通过 3 cm，但期限后关节仍有约 0.44° 范围变化。为满足跨规划包稳定保持的实现要求，修正版 r2 将相同目标判定改为位置/旋转范数各 1e-6，并增加“浮点扰动不能释放保持、真实伸手最后一步必须释放”的回归测试。r1 的日志与源码快照保留，最终结论以重新运行的 r2 为准。这是目标一致性判定修正，不是提高允许的实际执行误差。

## 资源安排

初版 r1 使用空闲 GPU 5（policy）与 6（sim）。随后其他任务占用这两张卡，等待队列尚未创建 r2 run 就被停止，原实验数据未受影响。修正版改用当时独立空闲的 32 GB GPU 7 容纳本实验的 policy 和 simulator 两个进程，保持、伸手顺序运行。启动器新增显式 `--share-policy-sim-gpu`，仍先拒绝有其他进程占用的 GPU；默认依然要求分卡。此调整仅解决实验资源可用性，不改控制时钟、模型采样、IK 目标或 tracker。

单卡复现时追加 `--share-policy-sim-gpu --policy-gpu 7 --sim-gpu 7`。两种资源安排均把设备分配记录在 run.json 中。

## 验证文件

- `runs/ik-hold-review/default-ik-replay.json`：原 IK 与保存源码的六个同输入重放窗口。
- `runs/ik-hold-review/goal-roundoff.json`：开发机上的单帧/批量目标数值差异。保持位置与旋转矩阵最大差约 2.98e-8，伸手末端旋转矩阵差约 1.86e-9，说明 r1 的 1e-9 判定确实会错误释放保持。
- `runs/ik-hold-review/comparison.json`：原版、首版与修正版的误差窗口、关节运动、约束及参考消费核验。
- 每项 run 内 `ik-hold-summary.json` 与 `commands.jsonl`、`execution.jsonl` 对齐。r2 额外断言期限后所有控制帧均处于保持且复用参考，跨包关节变化为零（数值容差 1e-5°）。

40 项检查覆盖旧接口、坐标/FK、连续条件、IK 限位/速度、静止目标抑制噪声先验、未到位继续收敛、新目标释放保持、浮点扰动及伸手最后一步识别。最终物理精度结论仍由 Arena 执行记录给出。
