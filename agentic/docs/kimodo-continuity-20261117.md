# 历史条件、重规划交接与关节连续性对照（2026-11-17）

## 范围与实现

所有修改、源码快照、原始输出与结果均位于独立 `vlm version`。共享 Kimodo 权重、HumanoidArena 和 SONIC 未修改。`--variant original` 仍为默认值；此前实验目录保留。

三组均使用冻结 Kimodo-G1-RP-v1、DDIM 50、约束 CFG 2、无文本/图像分支、50 帧未来画布、0.5 s 重规划、50 Hz SONIC 执行，夹爪始终打开。

| 变体 | 条件与交接 | 关节输出 |
|---|---|---|
| original | 原有多帧实测历史，原有直接交接 | 原始轴角投影 |
| handoff | 历史 mask 只保留最近一帧；未来第 0 帧条件改为当前实测几何姿态；到期目标放在未来 15/30/49 帧；从上一实际消费参考进行 0.2 s 五次曲线 SO(3)/位置混合 | 原始轴角投影 |
| bounded | 与 handoff 相同 | 在 XML 限位与上一参考 ±2 rad/s×0.02 s 的交集中，选最接近预测旋转的铰链角 |

`handoff` 是历史与交接的组合实验，不能据此单独归因到某一项。历史数组仍保留原有时间位置，只有 mask 稀疏化，未将预测动作伪装成实测历史。未来第 0 帧使用实测状态，发送动作交接则以执行器上一实际消费参考为边界，区分了两者。

`bounded` 同时处理有限转角、±π 分支和每步速度约束，避免先 unwrap 再 clip 导致跨限位跳跃。2 rad/s 是此次实验参数，不是机器人额定速度。此处不含加速度/力矩/碰撞/接触约束，不是完整运动可行性保证。未使用目标感知 IK，未用固定合法动作替换模型输出。

## 参考与误差定义

目标在启动时固定在世界坐标中。保持目标是初始实测双腕；伸手目标是初始关节中双肩 pitch 各减 0.15 rad 后的 FK，移动约 5.64 cm，保存了合法关节见证。期限为 1.2 s。不是箱子接触点，也不是抓取实验。

逐步统计在发送与执行一致的 50 Hz 时间轴上进行：

- 原始生成：Kimodo 旋转经 SO(3) 插值、FK 后到目标的距离。
- 原始投影：未经交接/限位处理的 29 关节参考 FK 到目标的距离。
- 发送参考：经过本变体所有处理后，参考 FK 到目标的距离。
- 传递：实际消费参考 FK 与发送参考 FK 的距离。
- 跟踪：实测腕点与实际消费参考 FK 的距离。
- 实际到位：实测腕点到固定目标的距离。

这些都是距离范数，不能相加。每轮预测中的未来约束点误差与实际发送区间不同，不混作同一指标。前 5 个控制步是固定姿态初始化；逐步对齐统计排除这 0.1 s。主要对比区间是 1.2 < t ≤ 4 s，共 140 步。

每轮保存未经处理的 `motion_features`、条件、mask、原始旋转 FK、`raw_actions`、交接参考、最终 `actions` 与实测日志。`plan-*.npz` 的 `projected_wrist_world` 仍表示原始 50 帧投影；新变体的执行统计必须用 `summarize_continuity.py`，不能用假定 actions 等于原始预测的旧 `audit_oracle.py`。

## 实测结果

8 组 × 200 控制步（每组 4 s），共 1,600 步物理仿真、64 次真实权重推理。每组剔除初始化 5 步后，有 195 步精确对齐；主表均取 1.2 < t ≤ 4 s 的 140 步平均，单位 cm，左/右分列于同一格。

| 任务 | 变体 | 原始生成 → 目标 | 发送参考 → 目标 | 实际 → 消费参考（跟踪） | 实际 → 目标 |
|---|---|---:|---:|---:|---:|
| 保持 | 原版 | 14.59/24.04 | 14.69/25.00 | 28.54/31.25 | 27.85/45.01 |
| 保持 | 短历史＋交接 | 8.52/12.64 | 7.91/11.85 | 10.09/11.62 | 14.41/17.95 |
| 保持 | ＋限位 2 rad/s | 12.18/12.76 | 14.33/15.85 | 11.03/8.86 | 19.86/15.19 |
| 保持 | ＋限位 4 rad/s | 8.46/13.16 | 8.30/13.05 | 9.57/10.30 | 13.39/19.94 |
| 伸手 | 原版 | 19.03/21.91 | 18.99/22.63 | 21.07/21.11 | 21.36/27.78 |
| 伸手 | 短历史＋交接 | 11.22/12.31 | 10.41/11.77 | 11.16/11.77 | 18.49/18.04 |

### 发送参考的合法性和连续性

下面统计实际执行的 195 个模型控制步，含第一个模型参考与初始化末参考的交接。没有把最终预测中未执行的 5 个动作计入分母。超限指发送的 29 关节参考，不宣称实测关节或动力学天然合法。

| 任务 | 变体 | 超限帧 /195 | 任意一步最大角度变化 | 重规划第一步最大变化 |
|---|---|---:|---:|---:|
| 保持 | 原版 | 107 | 254.487° | 115.587° |
| 保持 | 短历史＋交接 | 20 | 16.729° | 0.845° |
| 保持 | ＋限位 2 rad/s | 0 | 2.292° | 0.338° |
| 保持 | ＋限位 4 rad/s | 0 | 4.584° | 0.663° |
| 伸手 | 原版 | 104 | 338.657° | 143.374° |
| 伸手 | 短历史＋交接 | 22 | 17.137° | 0.787° |
| 伸手 | ＋限位 2 rad/s | 0 | 2.292° | 0.311° |
| 伸手 | ＋限位 4 rad/s | 0 | 4.584° | 0.541° |

限位组的变化上限分别为 2.292°/步与 4.584°/步，实测发送序列通过断言。大角度 ±π 分支跳跃被消除。交接组仍有片段内部超限和 16–17° 单步变化，因此不能只看重规划第一步平滑就认为整个参考合法。

### 剩余误差与结论

1. **历史/边界组织确实影响生成，而不只是美化执行。** 交接组未经后处理的模型 FK 误差明显降低，但仍为约 8.5–12.6 cm。这里是闭环结果；历史稀疏化、零帧条件与交接作为一组改变，不能单独归因。不同限位组的后续实测历史也不同，后续 raw 输出变化并不表示模型权重改变。
2. **关节合法化有效，但不自动满足手部目标。** 2 rad/s 组在主窗口对交接参考腕点平均改变约 4.8–6.3 cm；4 rad/s 组约 1.3–2.1 cm。放宽上限降低了部分轨迹滞后，但左/右手和保持/伸手的收益不一致，不能断言“只要调快就能到位”。
3. **仍存在身体姿态与根部运动的跟踪偏差。** 4 rad/s 组根位置相对参考的平均误差为保持 8.60 cm、伸手 8.22 cm；将参考放到实际根位姿后，腕点残差分别为 4.88/6.65 cm 与 4.12/6.79 cm。这两个分量的范数不能相加。此前固定合法参考的 2–3 cm 跟踪下限仍未达到。
4. **传递误差已很小。** 原版主窗口约 0.35–0.49 cm；两个修复变体在正确消费参考边界上重新编码后均低于 0.001 cm。剩余十几厘米的误差不能归因于这一级坐标传递。
5. **保留全部变体，不把新参数直接当作最终方案。** `original` 仍为默认；需要合法连续参考时显式用 `bounded`。4 rad/s 是补充参数对照，未验证加速度、碰撞、接触或更长时域。下一步优先考虑同时保持根/脚一致性与手部目标的约束投影/轨迹优化，并继续分开记录原始生成与修正量；当前证据不支持先接 VLM 来解决这些偏差。

### 可复现性与验证

- 8 组初始根位置与 29 关节值完全一致；运行时源码、权重、SONIC、关键 Arena 文件哈希一致。
- 两项原版重跑各 8 个 `50×417` 原始模型输出，与旧保持 r4 / 伸手 r1 的最大绝对差均为 **0**。原版对照行为保留。
- 本地和开发机均通过 30 项测试，包括 SO(3) 交接边界、真实历史 mask、跨 ±π 与跨窗口的限位/速度联合约束、合法慢动作保持。
- 新增旧审计入口保护：对经过处理的新变体，`audit_oracle.py` 明确要求使用 `summarize_continuity.py`，避免把处理后的关节与原始根轨迹混算。
- 单随机种子、每组 4 s，不能推出泛化成功率或长期稳定性。同步仿真会暂停等待模型，不是墙钟实时验证。夹爪始终打开，没有接触/抓取评价。
- 每组目录：`runs/continuity-{original,handoff,bounded,bounded4}-{hold,reach}-20261117-r1/`；包括原始预测、条件、逐步执行、汇总、录像与源码快照。`bounded4` 的实际 variant 仍是 `bounded`，显式传 `--joint-speed 4`。
- [一致性核验](../runs/continuity-review/validation.json)、[六组录像抽帧](../runs/continuity-review/six-run-contact-sheet.jpg)、[4 rad/s 录像抽帧](../runs/continuity-review/speed4-contact-sheet.jpg)。录像按控制步采样，抽帧标签使用仿真时间；视频播放 FPS 不代表控制频率。

## 复现

在开发机 `/root/workspace/humanoidVLA/vlm version`：

```bash
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python -m pytest tests -q
../cross_tracker/data/cache/envs/policy/bin/python scripts/run_oracle.py \
  --run-id continuity-bounded-hold-new --variant bounded --mode hold \
  --steps 200 --policy-gpu 2 --sim-gpu 3 --handoff-seconds 0.2 --joint-speed 2
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python \
  scripts/summarize_continuity.py runs/continuity-bounded-hold-new
```

将 `--mode` 改为 `reach`，`--variant` 改为 `original`/`handoff` 可运行另外两组。GPU 仅为示例，运行器会拒绝占用中的卡。run ID 必须新建。每轮保存源码、权重、tracker 与关键 Arena 文件哈希。
