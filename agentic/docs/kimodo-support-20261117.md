# 根部与双脚约束对照（2026-11-17）

## 保留的对照与本次改动

独立 `vlm version` 中，在上一轮 `bounded --joint-speed 4 --handoff-seconds 0.2` 基础上新增 `--support-constraints none|root|root-feet|root-feet-keyframes`。默认 `none` 保留原行为；上一轮运行数据、源码快照和 `continuity-manifest.json` 保留。共享 Kimodo 权重、SONIC、Arena 未修改，没有接入 VLM。

三组相同：最近一帧真实历史、未来零帧实测姿态、参考交接、XML 限位与 4 rad/s 速度约束，冻结 Kimodo、无文本与视觉分支、CFG 2、DDIM 50、每 0.5 s 重规划、30 Hz 未来表示与 50 Hz 执行。目标仍为固定世界坐标腕点；伸手只改变初始双肩 pitch 各 -0.15 rad，因此根与脚固定的约束与目标在运动学上相容。

- `none`：上一轮修复版，手部关键帧本来已有平滑根路径 XZ 条件，但没有持续骨盆/双脚条件。
- `root`：未来第 1–49 帧增加 17 个通道：平滑根 XYZ、heading 二维表示、骨盆相对平滑根的位置、完整旋转和零速度。
- `root-feet`：在 root 上增加双侧 ankle-roll 和虚拟 toe-base 的位置、旋转、零速度，以及 4 个原生接触标签，共 69 个通道。

支撑目标来自初始实测站姿转成的静态 Kimodo 特征，并在回合内固定，不能每轮重设为已经漂移的当前脚位。未来第 0 帧继续使用当前实测几何姿态；根脚目标仅覆盖第 1–49 帧，不覆盖手部通道。接触标签来自 Kimodo 的高度/速度启发式，并非实测接触力。这里没有硬覆盖输出、IK、站姿替换或 tracker 修改，生成偏差完整保留。

追加 `root-feet-keyframes` 密度对照：根条件仍覆盖未来 1–49 帧，双脚的 52 个通道仅在当前手部目标关键帧出现，排除第 0 帧。双脚目标、条件类型、权重和采样参数不变。该组用于检验逐帧双脚条件导致手部生成变差是否与条件密度有关。

## 误差口径

主要比较 1.2 < t ≤ 4 s，每组 140 个控制步。前 5 步是初始化。所有世界目标均固定在初始坐标系，不能用移动的身体坐标误差代替世界到位误差。

- 手部：原始 Kimodo FK → 目标；最终发送参考 FK → 目标；实际 → 消费参考；实际 → 目标。
- 根部：原始生成/发送参考/实测根相对初始根目标的漂移，和实际根相对消费参考的跟踪误差分别统计；包含 XY、高度、完整旋转和 yaw。
- 双脚：使用仿真 `left/right_ankle_roll_link` 原点，与模型 ankle-roll 点和独立 XML FK 对齐；不是脚底接触点。记录相对初始位置的偏移、水平偏移、高度偏差、跟踪误差及速度。未获接触力确认时，称脚部位移而非物理滑移。
- 单独检查 50 帧预测的未来 1–49 帧：位置特征误差、旋转 FK 误差、根偏差。这些预测窗口重叠，不混入实际执行统计。

每轮保存 support mask、静态支撑特征、完整未来条件与原始输出。分析器断言所有预期未来通道均为已知，且数值等于固定支撑目标。独立 XML FK 对照仿真脚点，检查新增脚部测量的坐标和关节映射。

root 组指定未来关键帧的手部 FK 误差约 1 cm，但实际发送区间的原始生成平均仍为左 3.6–3.7 cm、右 6.3–7.0 cm。主窗口内，右手在每次动作片段前/中段的原始生成误差约 6.8–8.2 cm，最后五步约 3.5–3.8 cm；实际右手最后五步仍约 7.1–7.2 cm，显示区间轨迹偏离与执行滞后共同存在。不能仅增加采样步数或只看关键帧分数来宣称问题已经解决。

同样历史、同样噪声的保持首轮预测（未来第 33 帧）提供了更直接的条件对照：原修复版手部 FK 8.49/6.38 cm，root 组 1.28/1.15 cm，逐帧 root-feet 组 4.35/2.84 cm。双脚约束的负面手部影响在闭环历史尚未分化时就已出现。把双脚移到关键帧能改善部分结果，但没有恢复 root 组水平，因此不能只归因于条件密度；冻结模型对组合条件的响应仍有限。

下一步优先检查手部目标在实际执行区间内的连续表达，以及参考速度与 tracker 滞后，而不是继续堆叠密集双脚条件或接入 VLM。若采用目标投影/IK，必须继续保留原始生成和修正后的轨迹分别统计。这里尚未实施连续手部目标或 IK。

### 验证、保留与限制

- 本地 34 项测试通过；开发机部署后同样验证。新增测试涵盖支撑通道、零帧保护、稀疏脚帧索引、肩部伸手与根脚相容性，以及模型/独立 XML 脚部 FK 一致性。
- 8 组初始根位置、姿态、29 关节、双脚位置/姿态完全相同，checkpoint、SONIC 和关键 Arena 文件哈希相同。首批六组源码一致；补充两组仅增加关键帧模式及分析功能，旧三种条件构造逐元素不变。
- `none` 两组各 8 次原始 `50×417` 模型输出与上一轮 bounded4 保持/伸手输出完全一致，最大绝对差为 0。上一轮结果与源码快照保留。
- 所有新增支撑 mask、目标值在每轮保存并通过分析断言；实际伸手关节见证和初始站姿的全部 69 个支撑特征差为 0。四个原生启发式接触标签均为 1。
- 独立 XML FK 与仿真脚点的最大差小于 1.5 微米，排除了新增脚部位置映射的厘米级错误。
- 所有组实际执行的 195 个模型参考均零关节超限，并保持 4 rad/s 变化上限；没有用硬改位置字段伪装 FK 满足约束。
- 单随机种子、每组 4 s，没有证明长期稳定、跨场景成功或接触可行。双腕 3 cm 到位比例仍低，不能宣布完成精确到位。无 VLM、无抓取、无 tracker 训练，夹爪保持打开；同步推理也不证明墙钟实时。
- 运行目录：`runs/support-{none,root,root-feet,root-feet-keyframes}-{hold,reach}-20261117-r1/`。保存逐步日志、条件、模型原始输出、参考、录像和运行时源码快照。

在开发机 `/root/workspace/humanoidVLA/vlm version`：

```bash

../cross_tracker/data/cache/envs/policy/bin/python scripts/run_oracle.py \
  --run-id support-root-feet-hold-new --variant bounded --joint-speed 4 \
  --support-constraints root-feet --mode hold --steps 200 --policy-gpu 2 --sim-gpu 3
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python \
  scripts/summarize_support.py runs/support-root-feet-hold-new
```
