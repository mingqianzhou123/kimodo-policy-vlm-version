# 实验 A：真值稀疏目标到 SONIC 执行

2026-11-17，开发机 T2M-PLUS，独立目录 `/root/workspace/humanoidVLA/vlm version/`。

**生成—执行链路已跑通，准确到达未通过。** 不接 VLM、DINO 或 ControlNet，不训练权重，
夹爪全程打开；这不是搬箱/抓取成功报告。先保留这一结果，再决定后续 VLM 与视觉注入。

## 有可达性依据的两组结果

- `oracle-hold-20261117-r4`：保持初始实测双腕位置和姿态。
- `oracle-reach-20261117-r1`：双肩 pitch 从初始值减 0.15 rad，FK 生成约 5.64 cm 的移动目标，
  同时提供一致的腕姿态和虚拟手端位置。目标对应的关节配置保存在 `target.json`。
- 两者均通过独立 XML FK / 限位核对，`reachability.json` 保存关节解。该检查证明运动学
  可达性，不证明动态可跟踪性或无碰撞。IK 只用于离线核验，没有修正任何下发动作。

每组 seed=1000，200 个 50 Hz 控制步（4 秒仿真时间），8 次重规划；期限固定为初始时刻后
1.2 秒。期限后的 140 步中，双腕同时距目标 ≤3 cm 的比例均为 **0%**。
这是单次诊断的逐步比例，不是多回合任务成功率。Arena 的任务结果为 timeout/success=false，
启动脚本的 completed 只表示诊断完整执行、记录齐全且无异常退出。

下表为均值，单位 **cm，左腕 / 右腕**。
前四行统计 18 个未来约束关键帧（排除当前帧 k=0，避免把已经错过的期限当作未来到达能力）；
后三行按 50 Hz 对齐，统计到达期限后的 140 步。不同时间集合和误差向量不能直接相加。

| 阶段 | 保持目标 | FK 移动目标 |
|---|---:|---:|
| 位置特征 → 目标 | 13.86 / 16.56 | 13.77 / 14.19 |
| 旋转 FK → 目标 | 13.35 / 16.87 | 13.25 / 14.34 |
| 29 关节投影 FK → 目标 | 13.12 / 17.53 | 13.55 / 15.56 |
| 投影额外偏差（投影 FK vs Kimodo FK） | 2.23 / 2.03 | 2.38 / 2.22 |
| 参考传递（Arena 实际消费 vs 生成命令） | 0.35 / 0.37 | 0.48 / 0.49 |

第一次规划在原始到达期限处，旋转 FK 的腕误差分别为：保持 9.05/6.07 cm，移动 9.84/5.72 cm。
因此后期误差并非全由闭环漂移造成。保持组最终实测误差 p95 为 62.8/82.9 cm，移动组为
46.8/60.5 cm；均值掩盖了后段的明显恶化，不能称作稳定保持。

## 已实现的链路

`Arena 仿真真值 → 世界系目标与实测历史 → Kimodo Y-up 条件 / mask → 冻结两阶段去噪器
→ 旋转 FK → 29 关节与 root 增量 → Arena 参考解释器 → SONIC → 实测反馈`。

- 历史来自实际执行状态，最多 100 个 30 Hz 帧；开始时仅预热 0.1 秒，早期历史不足时使用 mask。
  位置/速度/接触特征由姿态序列推导，接触特征并非实际接触传感器真值。
- 未来 50 帧；初次约束落在固定到达期限，期限过后使用 k=0/15/30/49 保持同一个世界目标。
- 未来 root XZ、双腕/虚拟手端位置和腕全局旋转经 checkpoint stats 归一化后进入
  `observed_motion` 与 `motion_mask`。保留所有原始预测，没有最后覆盖目标坐标制造零误差。
- 原生 A 构造器不加载视觉塔、ControlNet 或 hand head。采用 50 步 DDIM、约束 CFG=2、
  zero-text 分支、关闭 RTC 与后处理。没有把搬箱 instruction 当成“保持/前伸”的 motion text。
- 保存逐帧实测状态、实际消费参考、每次预测 NPZ、目标、视频、权重/源码哈希及源码快照。

世界↔Kimodo 坐标往返误差为数值零；独立 XML FK 与 Arena 实测腕位置的最大差异低于 2 微米。
因此现有大误差不能归因于坐标轴或腕部 body 索引接错。

## 排查和修正

1. **重规划边界位移锚点。** 原始做法从新预测起点计算 root 增量，但 Arena 累计在上一条
   已消费参考上，产生额外平移。现在第一条增量以 Arena 当前参考 root 为起点；后续增量沿
   生成轨迹计算。保留 `--root-anchor generated` 以复现对照。
2. **CFG 的历史输入。** 原 policy 会提前将历史覆盖到带噪 x；native CFG 现在保留原始带噪 x，
   仅由条件分支替换已知历史。`sampler-audit.json` 对相同条件和噪声比较了两种处理与 CFG=1/2。
   这不是宣称 CFG 或 50 步必然更好。
3. **实际消费参考仍包含运行时限幅。** Arena 启用了 root 旋转每步 26° 限幅。参考传递均值
   约 0.4–0.5 cm，但并非每一步都为毫米级；峰值与具体记录保存在 `aligned-summary.json`。
4. **目标可达性。** 直接平移 5 cm、锁住初始腕姿态的 offset 探索对照未找到精确限位内解
   （固定 root 的优化残差约 9.5 mm）。这不证明它绝对不可达，但不能作为严格真值结果。
   正式移动目标改用有已知关节解的 FK 目标。

此前 hold r1/r2/r3、offset r1/r2 都保留作为排查记录，不混入上面的两组结果。
首轮 hold r1 为 10 步、搬箱文本、无 CFG 的链路冒烟测试。完整过程共 7 次仿真、1350 控制步。

## 结论与下一步

当前 A 在没有视觉感知误差时仍未达到精度要求。生成端已有约 13–17 cm 的未来腕目标误差，
29 关节投影另引入约 2 cm，执行后还出现明显跟踪偏差。大跟踪误差可能来自难以跟踪的参考、
跟踪器配置或二者共同作用；本实验不能单独断言 SONIC 本身有问题。

下一步应先做两个有区分力的对照：给 SONIC 固定合法姿态/已知可达参考，测跟踪下限；
对原生 Kimodo 比较正确 motion text、约束设置和带关节限位的 IK/后处理，并分别报告修正前后误差。
在这之前不启动 B/C 视觉注入训练，也不据此挑选 VLM。正确的视觉目标无法自动消除这些误差。

限制：单场景、单 seed、短时起步实验，不代表 Kimodo 的能力上限；没有验证接触、抓取、门控、
RGB-D 定位或动态 motion text。仿真在同步推理时暂停，不能把每 0.5 秒仿真时间重规划理解为
真实墙钟 2 Hz。当前推理计时未单独同步 CUDA，也未覆盖全部 HTTP/执行开销，不作为延迟基准。
