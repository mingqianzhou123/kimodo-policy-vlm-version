# ToolBench scratch40k 低成功率：代码、逐回合证据与改进顺序

本次重新读取全部 1,800 份回合 summary，并逐条件核对官方 validated receipt；检查实际训练配置、4,000 条训练指标、转换审计、训练时源码快照以及当前已完成的调参结果。另用 CPU 做了当前实测状态的输入敏感性诊断，没有启动新训练或仿真。统计及诊断输出见 [analysis_evidence.json](toolbench_scratch40k_analysis_evidence.json)，复算入口见 [分析脚本](../scripts/analyze_toolbench_scratch40k.py)。

**核心判断：当前策略的首要问题是抓取和工具操作精度，同时存在可复现的当前本体状态反馈延迟。长动作执行段和有损手部表示会放大这些问题。现有证据不支持把失败主要归结为任务采样、训练数值异常，或单纯不会走路。** 反馈延迟和表示损失可以确认存在，但各自造成多少成功率损失，仍需受控实验。

**1. 失败发生在哪里**

总成功 71/1800（3.9444%），L1/L2 为 6/1200（0.50%）。1,729 个失败全部记录为 timeout；这说明没有 evaluator 侧 agent_exhausted，不能据此断言机器人没有失稳。官方环境本身没有失败终止。

| 难度 | 首次接触正确工具 | 曾将正确工具抬高 ≥8cm | 正确工具曾接触目标 | 最终成功 |
| --- | ---: | ---: | ---: | ---: |
| L0，600回合 | 445（74.17%） | 95（15.83%） | 14（2.33%） | 65（10.83%） |
| L1，600回合 | 415（69.17%） | 90（15.00%） | 41（6.83%） | 6（1.00%） |
| L2，600回合 | 411（68.50%） | 107（17.83%） | 85（14.17%） | 0 |

各列是同组回合中的边际事件计数，**不是严格嵌套的漏斗**：工具可能被推动而接触目标，L1/L2 的成功判据也不强制要求先抬起工具；不能将这些列直接相除并当作条件成功率。

L1 进一步拆分如下：

| 场景，均200回合 | 首次接触正确 | 曾抬起正确工具 | 工具接触目标 | 曾达到任务结果 | 最终成功 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BallMove | 152 | 44 | 19 | 球曾入圈6 | 5 |
| BallRetrieve | 128 | 9 | 3 | 球曾入目标区0 | 0 |
| IceBreak | 135 | 37 | 19 | 至少破一块9、破两块1 | 1 |

最差的 BallRetrieve-L1，正确工具最大抬升的回合中位数仅 **1.80mm**。其问题已出现在拿起钩子的阶段，尚不能主要归因于拉球轨迹规划。IceBreak 的“一块9次→两块1次”则提示还存在后续对准和连续操作瓶颈。

L0 中 95 回合曾达到8cm，只有65回合最终成功。核对 [官方成功判据](../../HumanoidToolBench/docs/ENVIRONMENTS.md)：包括 L0 在内，目标状态都必须连续保持50个控制步，即1秒。**短暂抬起不等于稳定抓取完成。** 这30个回合的差距提示抓持稳定性值得单独衡量。

另有一个具体数据差异：本机原始metadata确认1,803条L0全部为 `derived_l0_prefix`，在首次达到抬升阈值处截断；其中1,189条来自成功父轨迹、530条来自失败父轨迹、84条来自截断父轨迹。它们是有效的L0拾取前缀，却不包含本次评分要求的后续1秒保持示范。L1/L2仍可能提供间接的保持监督，所以不能说模型完全没见过抓持；但可以从父轨迹中保留真实后续、构建与L0指令匹配的保持片段，单独检验这项缺口。不能把末帧标签简单重复当成真实稳定抓持数据。

选择能力也有差距：L1/L2 首次接触正确工具，S 为461/600（76.83%），R 为365/600（60.83%）。但即使在相对容易的 S 条件，工具抬升和最终操作仍很差；增大语言模型或只改善工具分类，不能覆盖已经暴露的操作瓶颈。

**2. 已复现的实现问题：当前唯一的新实测状态没有进入本轮模型条件**

证据链：

1. [ToolBenchAdapter.to_observations](../kimodo_vla/benchmarks/toolbench/adapter.py) 每次请求只接收一个最新32维实测状态；上一段中间步骤用先前发送的动作目标补齐。
2. [KimodoPlanner.condition_history](../kimodo_vla/model/planner.py) 把历史编码后执行 `features[:-1]`，排除预测切点处的最新状态；`_condition_hand` 同样执行 `[:-1]`。
3. 因此，本轮刚收到的“肘关节实际偏了多少、手是否真的闭合”等反馈，没有进入本轮的运动/手部模型条件。上一轮测量保留在历史内，等到下一轮才发挥作用。
4. 默认 decoder 的实际执行采样也没有通过最新关节状态补偿这个缺口。其 `last_rot/last_root` 参数未用于当前 `_decode`；连续手的测量锚点在本次执行的采样位置上也不影响输出。

CPU 诊断保持全部旧历史、图像和预测不变，仅将最新肘关节增加1rad、最新两手闭合度从0改为1：

| 控制步 | 模型历史长度 | 有效运动条件最大变化 | 手部条件最大变化 | 固定预测的实际解码动作最大变化 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 | 0 |
| 81 | 49 | 0 | 0 | 0 |
| 163 | 98 | 0 | 0 | 0 |
| 245 | 100 | 0 | 0 | 0 |

对照：在第163步规划时，改变历史中第81步测得的肘关节，会让有效运动条件改变0.32719。因此这是**延迟一轮使用实测反馈**，不是所有测量永久失效。图像仍是当前图像，视觉反馈路径没有被本诊断否定。

上述 planner、features、adapter、dataset 四个文件与40k训练时的 `source_snapshot.tar.gz` 完全一致，排除了仅由后续代码修改引入的解释。诊断使用真实条件编码/解码路径和固定合成预测，不加载训练权重；它证明反馈路径缺陷，**不测量修复后的成功率**。

此处历史排除切点的设计与数据集 `[cut-H, cut)` 的定义一致，单看通用时间索引不一定是错误。但与 ToolBench“每轮只有切点有实测，其余为指令填充”的接口组合后，它削弱了闭环：执行器受接触阻挡，模型本轮仍主要看到自己曾想执行的动作。

改进应让当前测量进入本轮条件，同时保持目标是下一步操作员指令。可在固定历史容量内重新定义历史末端和未来起点，联合修改数据切窗、模型时间网格和解码插值；若允许改变模型结构，也可增加独立当前状态条件。**不要仅删掉 `[:-1]` 就宣称修好**，否则容易把历史与目标错开一帧。验证必须包括固定图像/旧历史/噪声、只改变最新状态时的条件与动作敏感性，以及 t→t+1、30/50Hz 相位和第一步行为检查。需要匹配新时间语义重训；旧40k模型上的直接改动只能算探索性诊断。

**3. 高优先级假设：长执行段放大了反馈问题**

实际配置为50个30Hz模型帧执行长度，受末预测帧限制，每段执行81/82个50Hz控制步，即 **1.62/1.64秒**，每秒约0.61次规划。当前实测反馈再延迟一轮，无法及时用于本段纠正；抓空、滑落、工具朝向偏差会继续随指令历史传播。

同样叫“chunk50”，不代表50个50Hz控制步。应保持预测未来50帧，比较只执行前50/30/20/10模型帧：对应约1.63/1.00/0.66/0.34秒再规划。更短执行只是候选改进，仍可能因为历史分布改变或跨段不连续而变差。

[现有演示转换](../kimodo_vla/benchmarks/toolbench/demos.py) 按执行长度决定哪些状态是真实观测、哪些是指令填充；已有 [recondition_toolbench.py](../scripts/recondition_toolbench.py) 可以重建相应历史。建议先用同一冻结checkpoint做 E50/E30/E20/E10 的开发集比较，再对有效的执行长度做历史匹配重训；RGB、目标动作、batch、优化器、训练预算保持可比。若严格检验训练/推理匹配，先比较相同推理 E20 下“旧历史训练”和“E20历史训练”，避免将历史变化和推理变化混为一个因素。

diffusion10→20/30应放在反馈与执行长度之后。增加去噪步数无法恢复被排除的实测状态，也无法恢复手部表示丢失的自由度。

**4. 已确认的表示损失：14维灵巧手被压缩为两个固定姿态缩放量**

[hand_closure/hand_targets](../kimodo_vla/benchmarks/toolbench/adapter.py) 先将每手7个关节投影成一个闭合度，再以 `closure × CLOSED_HANDS` 还原。单手输出仅位于固定的一维姿态集合中，无法独立调整拇指与另外两指。

全量原始数据审计表明：3,003条演示中 **1,168条（38.89%）** 存在大于0.01rad的手部重建误差，最大0.5rad。按帧加权、再对手部关节平均的MAE只有0.01863rad；这个小均值会稀释少数关键关节在闭合时的大误差。既有报告指出录制中有两种右手闭合姿态，当前映射只能保留一种。

它与“接触很多、拿起很少、短暂拿起后失败”现象一致，但仍未证明因果：手腕位置偏差、闭合时机不对，也能产生同样现象。应先做**表示上界诊断**，比较相同专家动作的原始手部关节、投影后手部关节，以及30Hz重采样后的抓取保持表现；必须控制相同初态和物体布局。现有54条运动回放场景不能还原录制场景，不能拿其任务成功率作上界。

若需保留现有统一手头容量，可先诊断固定姿态标定、不同右手模板和闭合时序；这些改变依然需要重新登记适配器身份、检查训练目标与执行姿态一致。若允许后续改表示，可比较每手“闭合度+拇指姿态”、低维synergy或完整7维关节头。后者属于结构研究，应与固定容量调参结果分开。

**5. L2零成功不能只解释为不会走路，也不能把到达指标当作移动操作成功**

L2 中 `reached_target_bench` 为592/600，首次移动方向朝向目标为598/600。但到达判据是进入0.40m范围且会锁存；**214/600在第1步已经满足**，592次中的首次到达中位步数只有65（1.3秒）。

在这592个到达回合中，487个从未抬起正确工具；其余105个的首次抬起也都发生在首次到达指标之后，没有一个在首次到达之前抬起。这个时序反映粗粒度到达指标的局限，不能等同于“模型错误地先走后拿”，更不能证明它会携带工具行走。

应新增离线诊断：抬起之后是否保持抓持、持工具期间的位移、工具与手的相对位姿、进入目标接触区时的工具端点位置/方向、到达后是否继续漂移。这些只用于解释失败，不输入策略，也不替代官方评分。L2策略在拿起前就大量失败，优先建立可靠L0抓持和L1工具操作，再检查移动中的保持和对准。

公开32维状态没有真实骨盆位置和朝向；adapter使用上一轮指令推算heading。当前漂移无法仅靠该状态完全观测，视觉仍需承担纠偏。运动回放已有长尾误差：30Hz路径相对原始命令回放终点差最大0.731m；但这是不同命令路径在接触场景下的误差，不能等同于真实策略导航误差，也不能据此认定是L2失败的单一原因。

**6. 训练预算、采样和损失：值得改，但不是已证实的主因**

40k×128共有5,120,000次窗口呈现；1,247,525个相邻重叠窗口，相当于约 **4.10遍窗口数据**。这不是4.10遍独立场景，3003也不是3003次互不重叠的完整工具操作：L0中包含从L1/L2尝试裁出的前缀。训练/验证划分需按原始轨迹来源归组，不能随机拆窗口，派生L0前缀和父轨迹也应在同一组。

实际窗口采样质量为L0 **32.35%**、L1 **27.37%**、L2 **40.28%**。因此“L2数据几乎没采到”不成立；18条件等权会提高L1质量，但同时降低L2总质量，不能默认必然改善。更有针对性的后续采样是抓取闭合/接触窗口和恢复阶段，而不仅是难度标签；同样需要单独验证。

| 最后1000更新所在区间 | 总loss均值 | body MSE | hand-state MSE |
| --- | ---: | ---: | ---: |
| 9k–10k | 0.03979 | 0.01591 | 0.01544 |
| 19k–20k | 0.03518 | 0.01479 | 0.01363 |
| 29k–30k | 0.03026 | 0.01334 | 0.01131 |
| 39k–40k | 0.02855 | 0.01304 | 0.01054 |

训练数值有限，指标总体下降，没有数值崩溃证据；但没有独立演示集上的多步推理误差、关节/末端误差、手部事件时序指标，所以无法区分拟合不足、泛化不足和闭环漂移。末期loss仍下降不等于成功率还会增长，也不足以证明训练已收敛。

训练优化的是冻结运动先验上的417维动作特征去噪及两个手部闭合度，最终评分关心的是细工具的抓握、方向、接触及持续结果。body loss又同时覆盖位置、旋转、速度、足接触等全身特征，包含由WBC执行、策略不直接控制的下肢运动。**平均特征误差低，不能保证工具端点误差小。** 应先离线报告分关节/末端厘米误差、工具朝向误差、闭合时刻偏差；容量/损失固定的实验可先增加诊断，不必立即调整权重。

当前完成的同组开发筛选（50k、SIMPLE峰值LR、E50/D10、seeds20000–20049，每条件50回合）：

| 采样 | L1/L2成功 | 全18成功 |
| --- | ---: | ---: |
| window_uniform | 1/600（0.17%） | 20/900（2.22%） |
| task_uniform | 1/600（0.17%） | 18/900（2.00%） |
| level_balanced | 1/600（0.17%） | 12/900（1.33%） |

这些结果来自 [已完成阶段表](../log/toolbench/tuning_20261027/stage_table3.md)。它们证明目前三种采样在该设置下都很低；不支持采样已解决问题，也没有足够证据判定采样优劣。与旧40k相比，它们还同时改变LR、训练预算、调度horizon和评估种子，**不能从2.22%低于3.94%推断学习率变小使性能下降**。`old40k_e30_d10`、`old40k_e50_d10` 目录当前没有完整summary或validated receipt，不能当作已完成的短执行段实验。

预算摸底应与计划中的预算匹配scratch重训区分：沿200k cosine轨迹得到的50k checkpoint，不等同于一开始就以50k为完整预算的模型。建议反馈修复的单因素对照先采用相同40k预算和相同LR调度，随后再用验证集学习曲线判断是否扩到100k/200k。

**7. 预训练和视觉：中期研究方向，证据强度低于上面的接口问题**

当前冻结DINOv3和LLM2Vec提供视觉/文本特征，冻结Kimodo-G1提供运动先验；这些与已经预训练过视觉-动作映射的机器人策略不是同一种初始化。91.7M可训练参数需要从本数据学习视觉到抓取/接触动作的映射；不能仅按“都有预训练、都训练40k”判定训练难度相同。

单路640×360图像直接变为224×224，相同预处理保证了训练/推理像素规则一致，同时也压缩了细工具、指尖和接触点。没有增强，冻结视觉编码器也可能使场景变化更难适应。现有checkpoint4000的换图/换文本测试只证明路径会影响数值，没有证明模型在看工具工作端或正确理解目标。

后续可用固定场景探针检查工具/目标遮挡、工具位置变化、指令变化与动作方向的关系；若离线和闭环证据支持，再比较保持视场的高分辨率/多裁剪、轻量色彩/平移增强、物体相对几何监督。公开策略输入只有左头相机；评测保存四路视频不代表策略可以额外使用腕相机。新视觉设计和任务策略预训练应明确作为新的实验分支。

作为背景，[论文Table III与实验设置](https://arxiv.org/pdf/2610.02089v1) 中ACT、DP的L1/L2成功率也很低；按表中18条件计算，ACT全18均值约0.72%、L1/L2为0；DP约4.00%、L1/L2为0.25%。这使scratch40k更接近较弱模仿学习基线的表现。它们是论文数据，没有在当前本机仿真版本重评，不能证明本策略显著超过ACT或等同DP；强机器人策略还有动作预训练差异。论文也明确L0来自派生前缀，且全方法执行完整chunk，故短执行实验属于本项目的后续推理研究。

**8. 建议的执行顺序和判定标准**

| 优先级 | 实验 | 控制变量 | 关注证据与后续决定 |
| --- | --- | --- | --- |
| P0 | 修复当前实测反馈可见性；同步训练目标时间语义 | 先做CPU/离线时间与敏感性检查；再与原40k同预算同LR scratch对照 | 当前状态必须进入条件；比较抓取率、稳定保持和L1/L2成功，尚不承诺提高分数 |
| P1 | 冻结模型E50/E30/E20/E10；随后匹配历史重训 | 同一开发环境种子、回合数、D10、3000步；第二阶段固定推理长度比较训练历史 | 若缩短执行提高拿起/保持或成功，再投入对应重训，检查跨段跳变 |
| P1 | 专家动作的手部表示上界诊断 | 原始/投影手关节、相同场景和初态、相同身体动作 | 分离姿态压缩、重采样和模型预测误差，决定是否需要新手部表示 |
