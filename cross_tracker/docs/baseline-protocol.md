# 第一轮朴素混训协议（2026-11-14 冻结）

目标是比较相同 Kimodo-VLA 骨干下，单源和双源数据的效果。此轮是独立的混训实验预算，不声称复现发布模型的 200k 步、batch 64 训练结果。所有模型从同一个官方 pt_419h checkpoint_1000000 开始；200 步 pilot 不用于续训。

## 数据与训练

- 固定 `balanced-v1.json`，SHA256 `831d19d9ae1b8ae215ac08e31b8678a17877af431fb9468c9392bc0a167e401b`。每来源箱子/拳击/导航分别 43/80/75 条训练，11/20/19 条验证；17 条隔离异常不回流。成功日志缺失的示教仍标记待核验。
- 任务→来源→轨迹→有效窗口均匀采样。只用修正标签和有效掩码；运动归一化沿用预训练统计量。
- 单源 30,000 次优化更新；双源 60,000 次。全局 batch 8，单 GPU micro-batch 2，梯度累积 4 次；训练 seed 42、43。三个单源、三个双源，共 12 次。
- 每来源预期抽到 240,000 个训练窗口，每任务每来源 80,000 个。双源步数加倍，保持每来源样本曝光；它仍多用了总数据和计算量，不能据此宣称固定算力下更优。
- 单源 warmup 1,000 步、双源 2,000 步，cosine 衰减至 0.1 倍。优化器、损失、模型结构沿用共享 Arena 配置；head 相机、30 Hz、100 帧动作历史、50 帧预测。
- 30k 是预先选择的第一轮预算，不是已证明收敛。按 pilot 约 0.44 秒/步估算，单源约 3.7 小时，双源约 7.3 小时；实际以正式运行日志为准。12 次串行约 66 GPU 小时，不含评测。

## checkpoint 和评测

| 项目 | 固定规则 |
| --- | --- |
| 单源计分 checkpoint | 26k、28k、30k |
| 双源计分 checkpoint | 52k、56k、60k |
| 计分 | 三个 checkpoint 成功率等权平均，不挑最佳，不把它们当独立训练 seed |
| 场景 seed | 1000–1099，共 100 个；不使用诊断 seed 17 |
| 每场景重复 | 1 次；`--seed` 与 `--episode_seed` 均使用同一个场景 seed，模型 `/reset` 同步 seed |
| 任务时限 | 箱子 1450、拳击 900、导航 1800 个 50 Hz 控制步，沿用固定 Arena 源码的任务脚本默认值 |
| 推理 | fp32，diffusion 10 步，执行 15 个 30 Hz 模型帧，RTC 关闭，timing=exact |
| 成功判定 | 固定 Arena 44a7222 的任务成功/失败条件；超时算失败；HTTP/仿真异常单列，不把无响应或部分回合记为有效结果 |

每个模型、任务、目标 tracker、checkpoint 使用完全相同的场景 seed。除 seed 外，还须记录实际物体重置 seed、控制器哈希、场景配置、episode 结果与错误。场景采用先前六项闭环验证使用的评测配置；导航不能换成采集场景。模型权重、修复桥接代码与参数都随运行保存。

先分别计算每任务/目标 tracker/训练 seed 的成功率和配对差，再对三个任务等权平均，得到 6×3 表。保留两个训练 seed 各自结果；100 个 rollout 和三个 checkpoint 都不是新增训练 seed。MimicLite 目标列在匹配 ONNX 与服务接入通过前记为缺失，不能填 0；MimicLite 示教可以作为训练来源。

## 执行顺序与记录

1. 完整读取并校验 ModelScope 29GB 包，确认权重查找结果；发现候选时先核对文件身份和接口。
2. 启动 SONIC 单源 seed 42；检查正式配置、实际样本数、有限损失、保存 checkpoint。单次目录为 `runs/baseline-sonic-s42-20261114/`。
3. SONIC 第二个 seed，再 TWIST2、MimicLite 两个 seed，最后三个双源组合。名单见 `runs/baseline-protocol-20261114/plan.json`。当前只启动首个作业，不把计划当成已提交队列。
4. 单源完成后先检查同 tracker 任务表现，再继续解释混训增益。若单源任务学不会，保留失败结果并整体修订为新协议版本，不能只给某一对比臂增加步数或事后删除困难任务。

`register_run.py` 保存配置、数据名单、项目源码、共享仓库 HEAD 和修改补丁。`train_baseline.py` 拒绝变化的代码/配置/名单、缺失的预检证据和繁忙 GPU；一个 run 只允许新启动一次。训练保存每 2k（双源 4k）checkpoint 和最新优化器状态。中断恢复必须另记恢复事件及起点；共享训练器没有保存精确数据迭代器/RNG 状态，不能宣称逐位相同的续训。

所有新增文件在 `cross_tracker`；共用模型与训练器不改。CCT 和后续方法沿用本轮的数据、预算、seed、计分 checkpoint 和评测配置，另设 run 目录。
