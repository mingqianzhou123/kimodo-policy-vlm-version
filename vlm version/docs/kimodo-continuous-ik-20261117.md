# 连续执行区间手部目标与 IK 轨迹投影（2026-11-17）

## 问题与实验边界

沿用上轮最好的 `bounded + 4 rad/s + root`，不接 VLM，不训练权重，不扫描 CFG/采样步数。
用户要求：把手部条件覆盖到实际执行区间；若不能稳定双腕 3 cm，停止调软条件，转向投影/IK。

验收定义：到达期限之后 **每一个实际执行帧，两只腕的世界位置误差都 ≤3 cm**。
主对照使用 `1.2 < t ≤ 4 s` 的 140 个 50 Hz 控制帧；IK 另外执行到 8 s。
报告均值、P95、最大值和同时达标帧比例，不把均值 <3 cm 当成稳定达标。
只验证当前初始化、随机种子 1000、固定站立和约 5.64 cm 伸手任务；未做接触、抓取、多种子或动态目标。

## 保留与实现

- 本地和开发机均保存 `snapshots/support-before-continuous-20261117/`，逐文件验证原 `support-manifest.json` 的 108 个 SHA-256。
- 又保存完整 `snapshots/continuous-before-ik-20261117/`，保持纯连续软约束版可复现。
- 原版默认选项不变；每个新 run 独立保存源码、配置、条件 mask、原始输出、修正后参考、执行日志和视频。
- 开发机仅修改 `/root/workspace/humanoidVLA/vlm version/` 下实验代码；共享 Arena、SONIC 和 Kimodo 权重只读。

`--hand-constraints continuous`：每次 0.5 s 重规划，给将执行的 25 个 50 Hz 控制点所覆盖的 30 Hz 未来帧 1–15 加双手条件。未来零帧保留实测边界，原有远端关键帧和密集根部条件保持。非整相位时包括右侧插值端点。

保持路径来自初始实测姿态；伸手路径来自初始关节到合法肩关节终点的 1.2 s 五次平滑插值，再 FK 得到手腕/虚拟手端位置与腕姿态。目标绑定绝对 episode 时间，不随重规划重置。合法关节路径**只生成条件目标**，不作为 Kimodo 的输出动作。期限后两手保持固定终点。

`--trajectory-projection ik`：连续条件的 Kimodo 原始生成 → 原有交接与限位处理 → 逐控制帧 IK → SONIC。IK 以处理后的 Kimodo 关节为姿态先验，求解 29 个关节；同时匹配双腕位置/姿态和初始双脚位姿，投影参考根位姿固定于初始实测值。原生根部条件仍保留。关节解限制在 XML 限位与上一已发送关节 ±4/50 rad 的交集中。

投影目标函数：位置残差权重 100，旋转向量残差权重 20，模型姿态先验与上一关节姿态权重各 0.1。`least_squares` 最多 60 次目标函数评估，单独记录求解收敛、手脚残差、关节修正量和耗时。这些权重未做参数扫描。

IK 不接收目标关节 witness，只接收目标手脚位姿、生成关节先验和上一参考关节。它是运动学投影，没有碰撞或动力学约束；当前只用在简单站立到达诊断。模型原始输出、投影前参考、投影后参考与实际执行四层分别记录，不能把投影后的精度归功于冻结生成器。

## 纯连续软约束结果

单位 cm，左右腕分别列出。相同 1.2–4 s 区间。

| 任务 | 约束 | 原始生成 FK | 发送参考到目标 | 实际到目标 | 双腕同时 ≤3 cm |
|---|---|---:|---:|---:|---:|
| 保持 | 原关键帧 | 3.60 / 6.33 | 3.56 / 5.20 | 3.71 / 6.51 | 3.57% |
| 保持 | 连续执行区间 | 1.54 / 2.04 | 1.42 / 2.23 | 1.81 / 2.88 | 55.00% |
| 伸手 | 原关键帧 | 3.67 / 6.97 | 3.46 / 5.86 | 3.86 / 6.44 | 10.71% |
| 伸手 | 连续执行区间 | 1.72 / 2.01 | 1.52 / 2.11 | 2.16 / 2.30 | 70.00% |

连续保持实际 P95 为 3.38 / 4.13 cm，最大 4.49 / 4.68 cm；连续伸手 P95 为 4.11 / 3.72 cm，最大 4.87 / 4.67 cm。两项均未达稳定标准，因此停止软条件调参并进入 IK 对照。

原关键帧保持的 8 份原始 50×417 输出与上一轮根部版逐值相同，最大差 0。连续保持与伸手各 8 个预测窗口的实际执行条件值和 mask 全部通过独立重建核对；参考传递误差低于显示精度。实际误差不等于各阶段误差范数相加。

## IK 结果与剩余问题

在相同 1.2–4 s 区间：

| 任务 | 投影前参考到目标 cm | 投影后参考到目标 | 实际到目标 cm | 实际最大 cm | 双腕同时 ≤3 cm |
|---|---:|---:|---:|---:|---:|
| 保持 | 1.20 / 1.86 | 均 <0.01 mm | 2.95 / 1.64 | 3.40 / 2.57 | 47.14% |
| 伸手 | 1.38 / 1.81 | 均 <0.01 mm | 2.47 / 1.99 | 3.14 / 3.05 | 92.86% |

IK 的整段和后半段：

| 任务 | 时间区间 | 实际均值 cm | 实际最大 cm | 双腕同时 ≤3 cm |
|---|---|---:|---:|---:|
| 保持 | 1.2–8 s | 2.74 / 1.70 | 3.42 / 2.57 | 62.35% |
| 保持 | 4–8 s | 2.59 / 1.75 | 3.42 / 2.30 | 73.00% |
| 伸手 | 1.2–8 s | 2.35 / 2.17 | 3.14 / 3.05 | 97.06% |
| 伸手 | 4–8 s | 2.27 / 2.30 | 2.68 / 2.83 | 100.00% |

**只可认定伸手后半段通过；“保持和伸手从期限后全程稳定双腕 3 cm”尚未通过。**
尤其不能声称 IK 全面改善了实际误差：保持在主对照区间的达标比例从连续软约束的 55% 降到 47.14%，尽管最大误差从约 4.68 cm 降至 3.40 cm。精确参考与实际跟踪偏差会按方向叠加或抵消，所以参考变准不保证每一只手的实际均值单调改善。

两项 IK 共 32 个窗口、800 个求解参考帧全部报告收敛（实际执行 790 个模型参考帧，另有 10 个初始保持帧，末窗口未消费部分不进入执行统计）。运动学目标最大残差：腕 <0.0021 mm，脚 <0.0070 mm。这是 FK 数值精度，不是机器人实物精度。

限位违规 0；最大关节单步变化保持 3.27°、伸手 3.85°，均低于 4 rad/s 对应的 4.58°。参考传递最大误差 <2e-15 m，故当前厘米级差异不来自参考传输/坐标解释。

剩余可定位为**准确参考与物理执行之间的误差**，但不能简单宣称 SONIC 存在不可突破的 3 cm 下限：

- 根部跟踪均值保持 2.42 cm、伸手 2.17 cm，其中高度偏差约 2.1 cm；XY 偏差分别 1.22 / 0.34 cm。
- 在实际根位姿下比较关节姿态的腕误差，保持 2.37 / 2.20 cm，伸手 3.10 / 2.66 cm。根位姿与关节姿态的误差向量会互相抵消，范数不能相加。
- 虽然腕位姿固定，IK 仍跟随模型先验改变冗余关节：1.2–4 s 左腕 roll/肩 yaw 的参考范围约 21–22°。这提供了下一步明确检查对象：目标保持时不必要的关节运动及其跟踪偏差。仅凭本轮相关现象，尚不能证明它是全部残差的原因。
- 之前固定合法参考能在保持任务通过同一区间双腕 3 cm，因此不能把本轮失败直接解释为 tracker 的能力极限。

下一步范围应限定在投影轨迹的时间连续性/冗余姿态稳定、以及执行侧稳态误差；不再扫描 Kimodo 软条件，也不急于接 VLM。

运行速度另未达实时：每个 0.5 s 轨迹包，原生 Kimodo 平均约 1.12 s，IK 平均保持 2.99 s、伸手 3.32 s（最大 3.85 / 4.85 s）；合计仅这两项已约 4.1–4.4 s。当前实现是同步仿真诊断原型，不能作为实时控制器交付。

## 复现

在开发机 `vlm version` 内，使用空闲且不同的 policy/sim GPU：

```bash
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python scripts/run_oracle.py \
  --run-id continuous-new-hold --mode hold --steps 200 \
  --variant bounded --joint-speed 4 --support-constraints root \
  --hand-constraints continuous --policy-gpu 4 --sim-gpu 5
```

关键帧对照改成 `--hand-constraints keyframes`。IK 改成 `--steps 400` 并增加 `--trajectory-projection ik`；伸手改 `--mode reach`。所有 run-id 必须新建，脚本拒绝覆盖已有实验。

```bash
PYTHONPATH=. ../cross_tracker/data/cache/envs/policy/bin/python scripts/summarize_continuous.py runs/continuous-new-hold
```

同步 HTTP 推理会暂停仿真时钟；即使动作精度达标，也不代表达到每 0.5 s 的实时重规划期限。
